# Canvas PDF 0.1.1 修正與審查

> 本文保留本機修正驗收當時的紀錄；後續原始碼入庫與暫停狀態以 [STATUS.md](STATUS.md) 及 repo 提交紀錄為準。

本輪重現了使用者回報的「點選／雙擊無法編輯、右側沒有文字」。OCR 推論本身有產生結果；選取、編輯入口及工作模式有實際缺陷。以下修正包含於 0.1.1。

## GitHub 檢查

失敗的 [run 42253482744](https://github.com/show940125/Html-in-Canvas/actions/runs/42253482744) 屬於 Canvas Clipper：入口動畫後的原生 Canvas 命中幾何未刷新，dark-theme 讀者備註輸入未保存。遠端 commit `d97b664587d242ec2085e1b76fd9768d238e1d48` 已修正，最新 [run 42254661174](https://github.com/show940125/Html-in-Canvas/actions/runs/42254661174) 通過。

Canvas PDF 原先沒有自己的 CI。本輪新增 `.github/workflows/canvas-pdf.yml`，涵蓋固定資產、型別、單元測試、無本機驗收輸入的建置，以及雙 ZIP／來源摘要檢查。瀏覽器、IME、GPU 與翻譯服務的驗收另有腳本。本輪保持本機修改，未執行 pull、merge、commit 或 push；新增 workflow 尚未在 GitHub 遠端執行。

## 本輪驗證

- TypeScript 與 **21 項單元測試**通過。
- 原生 HTML-in-Canvas 與明確停用 CanvasDrawElement 的 DOM 模式各 **20 項實際 UI 檢查**通過：點選／雙擊、右側文字、中文提交、Escape 取消、穩定選取、真實掃描 OCR、搜尋校正、可見重建、單步復原／重做、取消重辨、強制整頁 OCR、獨立 PDF 重開、重複文字保護及明確點陣化輸出。測試全程斷網，使用原創文件。`scripts/ocr_edit_acceptance.py`
- 五組繁中文字型回歸案例通過：原生模型與 PyMuPDF 擷取結果一致，包含原先失敗的「生死」。`scripts/font_commit_probe.py`
- 原有原生 UI 驗收重新執行通過，包含實際移動圖片、復原／重做、OCR、搜尋 PDF 及無遠端 OCR／程式碼請求。`scripts/acceptance.py`
- 打包後以 `scripts/verify_package.py` 核對雙 ZIP／逐檔摘要、授權與對應原始碼，解壓後執行離線 OCR、實際 WebGPU 及上述兩種 UI 流程。最終檔案身分及執行結果見外部 `DELIVERY.md`；單純建置不等同瀏覽器驗收。

逐次 JSON 在 `output/`；本機離線包的 `verification/index.json` 列出附件。0.1.0 歷史紀錄保留日期與限制，未在本輪重跑的 medium、多緒矩陣及翻譯服務不列為本輪新驗證。

## 使用與驗收邊界

更新至 0.1.1 後，在 `chrome://extensions` 重新載入插件，再重新整理編輯分頁。更新前可先下載專案 ZIP 保存編輯成果。原生文字直接點選／雙擊；掃描頁先 OCR，再選取文字框。

本輪未取得使用者當時操作的 PDF，重現使用原創原生／掃描文件。實體 IME、廣泛真實文件保真度、人工 OCR 金標及 loopback MIME 穩定性仍依 `ACCEPTANCE.md` 保留驗收邊界。新程式能檢查寫回失敗與不支援的原生段落，並提供原因或明確替代輸出；本輪結果不代表所有 PDF 均可直接修改。
